# 技术细节：希沃管家是怎么锁屏的，以及这份代码为什么这么写

> 本文面向想改代码 / 想验证实现的人。只想用工具请看 [README](../README.md)。

## 1. 结论：锁屏不是系统锁屏，是应用层的一块全屏置顶窗口

1. **触发**：锁屏是希沃集控后台下发的一条指令（与关机/重启/打铃同级，支持周期性指令计划）。解锁只有**扫码（教师希沃账号）/ 锁屏密码 / 激活码**三种，属于服务端授权；集控到期后忘记撤销锁屏指令，就会出现"设备没关联学校也照样锁屏"的异常锁屏。
2. **呈现**：客户端锁屏界面由 `SeewoServiceAssistant.exe` 提供——一个**全屏 + `WS_EX_TOPMOST` 窗口**（标题固定 `希沃管家`，窗口类 `Chrome_WidgetWin_0`），靠反复调用 `SetWindowPos` / `ShowWindow` / `BringWindowToTop` / `SetForegroundWindow` 维持置顶与前台。
3. **热键限制**：走 `SetWindowsHookEx(WH_KEYBOARD_LL)` 低级键盘钩子，另配 `RegisterHotKey` 系统热键。开源工具 HugoHSSA 只要拦掉 `WH_KEYBOARD_LL` 的安装就能解除热键限制，反证了这条链路。
4. **推论**：让那块窗口消失（或让那个进程不存在）就等于解除锁屏。这也是本程序的基本思路。

## 2. 真机取证（只读静态检查，未执行、未修改）

对一台真实安装的希沃管家做字符串层取证：

| 项目 | 结果 |
| --- | --- |
| 路径 / 版本 | `C:\Program Files (x86)\Seewo\SeewoService\SeewoService_1.6.7.4018\SeewoServiceAssistant\SeewoServiceAssistant.exe`，文件版本 **9.3.3**，产品名"希沃管家"，广州视睿电子科技，95,451,032 字节 |
| 位数 | PE `Machine = 0x014C` → **32 位**（因此 IFEO 必须同时写 64 位与 `WOW6432Node` 两个注册表视图） |
| 内核性质 | 同目录 `icudtl.dat`、`resources.pak`、`chrome_100/200_percent.pak`、`libEGL/libGLESv2`、`vk_swiftshader`、`ffmpeg.dll`、`snapshot_blob.bin`、`LICENSES.chromium.html`，并命中字符串 `Electron` → **CEF/Electron 应用** |
| 窗口类 | UTF-16 字符串命中 `Chrome_WidgetWin` → 与开源工具记录的 `Chrome_WidgetWin_0` 吻合 |
| 窗口/置顶 API | ASCII 命中 `SetWindowPos`、`SetForegroundWindow`、`BringWindowToTop`、`SetLayeredWindowAttributes` |
| 键盘钩子 | ASCII 命中 `SetWindowsHookExW`、`UnhookWindowsHookEx` |
| 热键注册 | ASCII 命中 `RegisterHotKey`、`UnregisterHotKey` |
| **不是**系统锁屏 | `LockWorkStation`、`SwitchDesktop`、`WTSDisconnectSession` 均未出现 |
| **没有**禁用任务管理器 | `DisableTaskMgr`、`taskmgr.exe` 均未出现（至少这一版没走组策略那条路） |
| 附带发现 | 同目录 `ShowTaskBarTool.exe` 命中 `FindWindowW`/`SetWindowPos`/`TaskBar`，看似"把任务栏弄回来"的小工具 |

扫描方法：流式按块读入、Latin1 解码后做子串匹配（ASCII 导入名会原样出现），UTF-16 关键字用 `Encoding.Unicode` 转成同样的 Latin1 串再匹配。

**局限**：这是字符串层证据，不是反汇编；`WH_KEYBOARD_LL` 是常量、不进字符串表，它由"HugoHSSA 只拦 `WH_KEYBOARD_LL` 就能解除热键限制"这条旁证支持。

## 3. 锁屏判据（`LockDetector`）

四个条件同时满足才算"锁屏窗口"：

| 条件 | 默认值 | 为什么 |
| --- | --- | --- |
| 标题 | 精确等于 `希沃管家` | HugoWndRec 记录的过滤条件就是"标题完全相等" |
| 类名 | 含 `Chrome_WidgetWin` | Electron/CEF 的窗口类；真机取证命中过该串 |
| 属主进程 | 含 `SeewoServiceAssistant` | 与真实的 exe 名一致（含变体也能命中） |
| 状态 | 可见 + `WS_EX_TOPMOST` + 全屏 | 全屏判定用"左上角≈0 且尺寸≈屏幕"，容差 100px，与 HugoUtils 的 `IsWindowFullScreen` 一致 |

三者都做成可配置（`--lock-title/--lock-class/--lock-process`），因为希沃换版本可能改实现；`--lockscan` 会把当前所有「可见+置顶+全屏」窗口连同标题/类名/进程名/尺寸列出来并标注命中情况，用于校正判据。

**为什么"可见"这个条件很关键**：命中后若选 `hide` 动作，窗口被 `SWP_HIDEWINDOW` 隐藏后 `IsWindowVisible` 变假，于是它自动退出候选集合 —— 不会出现"一遍遍对同一个隐藏窗口重复动手"的死循环。

## 4. 拦截手段的三层实现

```
第 1 层 IFEO     目标 exe 一被 CreateProcess → Windows 转去启动我们的 --ifeo-stub
                 → 桩进程立刻退出，目标"挂起后永远没跑起来"；启动方收不到任何错误
第 2 层 ACL      icacls 给 exe 加 Everyone:(DENY)(X) → CreateProcess 直接 ERROR_ACCESS_DENIED
第 3 层 锁屏触发 / 看门狗   已在跑的实例：默认只在检测到锁屏窗口时处理；也可切成无差别
```

### 4.1 IFEO 的几个设计点

- 值写在 `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\<映像名>`，
  **两个注册表视图都写**（`RegistryView.Registry64` + `Registry32`），因为真机目标 exe 是 32 位。
- 目标挂起、调试器退出 ⇒ 目标永不执行；桩进程（`--ifeo-stub`）只写一行限流日志就退出，不提权、不弹窗。
- **覆盖前备份**：原来的 `Debugger` 值（如果有）备份到 `HKLM\SOFTWARE\SeeowKiller`，`--block off` 时还原；只删自己写的那一份，不动别人的值，也不删整个 IFEO 子键（里面可能有微软的 mitigation 设置）。
- **自愈**：看门狗每 ~15 秒检查一次已启用的 IFEO 是否被希沃的文件保护抹掉，抹掉就重挂并在日志留痕。

### 4.2 ACL 层

- `icacls "<path>" /deny "*S-1-1-0:(X)"` 禁止执行，撤销用 `/remove:d "*S-1-1-0"`；用**众所周知的 SID**而不是 "Everyone" 名字，避免多语言系统上匹配失败。
- 目标路径来源：正在运行的进程（`QueryFullProcessImageNameW`）+ 常见安装目录（`Program Files` / `Program Files (x86)` / `ProgramData` 下名字含 seewo 的目录），也可用 `--block-path` 手填、`--no-discover` 只用指定的。
- 需要 `WRITE_DAC`：普通用户对自己拥有的文件本来也有这个隐含权限，实践中最稳的还是以管理员运行。

## 5. 踩过的工程坑（改代码时别踩回去）

1. **不要给项目加自定义 `app.manifest`**。.NET 的 apphost 自己会写 manifest，再叠一份会出现
   `The application has failed to start because its side-by-side configuration is incorrect`（0x36B1），exe 直接起不来。默认 manifest 已含 `asInvoker` + Win10 兼容声明；要提权用程序自己的 `runas`。
2. **GUI 子系统 exe 的输出**。`OutputType=WinExe` 时，在 PowerShell 里 `.\x.exe --status` 不会被等待、也捕获不到输出。`ConsoleBridge` 的策略是：stdout 句柄有效（管道/文件）就老实写句柄；句柄无效才 `AttachConsole(ATTACH_PARENT_PROCESS)`。另外**不要**在句柄就是控制台时强设 UTF-8 输出编码，否则 cmd 里中文乱码。
3. **`icacls` 会把 `(X)` 打成 `(S,X)`**（S=Synchronize）。判断"是否已禁止执行"不能找 `"(X"`，要把 `(DENY)` 后面的权限标志位拆开，认 `X/RX/F` —— 否则状态永远显示"可执行"。`--selftest` 里留了 8 条样例回归。
4. **`Global\` 互斥体的坑**：普通用户没有 `SeCreateGlobalPrivilege`，创建 `Global\` 对象会抛 `UnauthorizedAccessException`；直接当成"已有实例"会让程序永远起不来。正确做法是先用 `Mutex.OpenExisting` 判断名字是否真被占用，否则退化成 `Local\`。
5. **计划任务 XML 的编码**：非 ASCII 的 XML 交给 `schtasks /Create /XML` 时用 **UTF-16 LE + BOM** 最稳（`Encoding.Unicode`）。
6. **`.ps1` 里的中文**：Windows PowerShell 5.1 按 ANSI 读脚本，`build.ps1` 必须带 **UTF-8 BOM**；here-string（`@" ... "@`）在 LF 换行的文件里容易被 5.1 解析失败，脚本里改用字符串数组 + `-join`。

## 6. 测试记录

在开发机上实测通过的项（打的是**自造的假锁屏窗口**与改名进程，未接触真实希沃环境）：

| 项 | 做法 | 结果 |
| --- | --- | --- |
| 锁屏识别（默认判据） | `tests/FakeLockWindow` 造类名 `Chrome_WidgetWin_0`、标题 `希沃管家`、全屏置顶窗口 → `--lockscan` | `[命中锁屏] ... 标题=√ 类名=√ 进程=√ topmost=True fullscreen=True visible=True` |
| kill 动作 | `--intercept-once --on-lock=kill` | 属主进程被结束 |
| hide 动作 | `--intercept-once --on-lock=hide` | 窗口被隐藏、进程存活；随后 `--lockscan` 显示无候选 → 无重复误判 |
| 托盘默认策略 | `--watch` + 拉起假锁屏 | 日志记录完整判据并解除 |
| 无差别策略 | `--watch --policy=kill --targets=X` | 不看窗口，按进程名结束 |
| 无差别/保险丝 | `--once --never-kill=X` | 进程被放过 |
| ACL 层端到端 | `--block-acl on/status/off` + 尝试启动 | 拦截后启动报 `Access is denied`，撤销后恢复，状态识别正确 |
| 自启任务 XML | `--print-task-xml` + XML 解析 | 结构正确（`RunLevel=HighestAvailable`、LogonTrigger/BootTrigger、`ExecutionTimeLimit=PT0S`） |
| 单实例 | 起两个实例 | 第二个自动退出 |
| 输出重定向 | `Start-Process -RedirectStandardOutput` | 输出正确落文件 |

**未验证 / 需要在真机确认**：

- IFEO 的真实注册（需要管理员且会改 HKLM，未在开发机执行）——首次使用请用 `--block status` 复核并记住 `--block off`。
- `--on-lock=hide` 在真实希沃（权限更高）下能否隐藏成功；失败会自动退回杀进程。
- 真实锁屏场景下的判据是否仍然成立（版本迭代可能改窗口特征）。

## 7. 目录结构

```
SeeowKiller/
  Program.cs          入口 + 各命令行模式（watch/once/status/lockscan/intercept-once/block/block-acl/install/...）
  AppConfig.cs        配置与参数解析（策略、锁屏判据、目标、保险丝）
  LockDetector.cs     锁屏窗口识别（EnumWindows + 标题/类名/进程/置顶/全屏）+ 隐藏 + 结束属主
  ProcessKiller.cs    按进程名结束（无差别模式、保险丝、外部结束计数回填）
  Blocker.cs          IFEO 假调试器 + ACL 拒绝执行 + 备份还原 + 自愈
  AutoStartManager.cs 计划任务（登录/SYSTEM 开机）与 HKCU Run 兜底
  TrayApp.cs          托盘、循环、硬拦截自愈
  Elevation.cs        runas 提权、SeDebugPrivilege
  ConsoleBridge.cs    GUI exe 的控制台输出兼容
  SingleInstance.cs   单实例互斥体（含 Global 权限降级）
tests/FakeLockWindow/ 造"假锁屏窗口"用于验证
```
